# 다음 달 대출 연체 확률 데모

실개인정보 없이 만든 2,000명 합성 고객 데이터와 한국어 브라우저 데모입니다. 실제 은행 검증 모델이 아니며 대출 승인, 금리, 추심 등의 의사결정에 사용할 수 없습니다.

## 실행

Python 3.11 이상에서 `pip install -r requirements.txt`, `python train.py`, `node verify.cjs`를 실행합니다. `python -m http.server 8000 --directory docs` 후 http://localhost:8000 에서 확인합니다. Python 학습 결과와 JS 추론은 최종 테스트 400명에서 최대 절대 오차 3.33e-16으로 일치합니다.

## 목표와 시점

기준 시점은 가상 월 30의 종료입니다. 목표 `next_month_late=1`은 월 31의 약정 납입일을 1일 이상 넘긴 경우입니다. 30일 이상 연체 또는 부도를 뜻하지 않습니다. 이력은 월 1~30에 각 납입의 연체일수를 기록합니다. 미래 목표, 생성 과정의 잠재 변수 및 확률, 고객 ID는 입력에서 제외합니다. 고객별 1개 행이며 고객을 학습/검증/테스트로 분리합니다. 월별 rolling backtest는 수행하지 않았습니다.

## 생성 가정

seed 20261007. 소득은 로그정규분포로 100~1,500만원, 잔액은 소득의 3~24배, 잔여 기간은 12~120개월, 금리는 연 3~16%입니다. 대출 상환액은 잔여 기간 동안 고정금리 원리금균등상환을 가정합니다. 다른 부채 상환액은 월 소득의 2~35%입니다. 신용점수는 한도 사용률과 잡음에 연계하고 과거 연체에 따라 하락합니다. 저축과 근속은 안정성을 나타내는 가상 변수입니다. 기록 이전에 대출이 실행되어 30개월 모두 관측 가능하다고 가정합니다. 현재 잔액으로 과거 잔액을 복원하지는 않습니다.

연체 확률은 부채상환비율, 사용률, 신용점수, 근속, 저축, 관측되지 않는 고객별 잡음과 직전 연체에 연계합니다. 과거 이력에 완만한 주기 효과가 있으며 다음 달 목표는 최종 시점에서 별도 Bernoulli 추출합니다. UI 랜덤 버튼은 동일 생성 스크립트가 만든 200개 가상 프로필 중 하나를 선택하므로 모든 파생값과 이력이 일관된 조합입니다. 반복 선택할 수 있습니다. 실제 한국 은행 분포를 추정하거나 보정하지 않았습니다. 은행이 흔히 수집할 법한 예시 변수이며 실제 기관의 수집 항목을 검증한 목록이 아닙니다.

## 모델 비교

층화 분리: 학습 1,200 / 검증 400 / 테스트 400. 학습 안에서 4-fold CV Log loss로 18개 하이퍼파라미터 설정(로지스틱 4, 포레스트 6, 부스팅 8)을 자동 탐색합니다. 표준화는 로지스틱 파이프라인 내부에서만 학습합니다. 각 계열의 최선 후보 중 검증 Log loss가 가장 낮은 모델을 선택하고 재학습 없이 고정해 최종 테스트를 1회 평가합니다. 탐색 결과와 seed는 docs/report.json에 저장됩니다. 확률 보정은 별도로 하지 않았습니다.

선택: 로지스틱 회귀. 최종 테스트 ROC AUC 0.8670 / PR AUC(AP) 0.6322 / Brier 0.05604 / Log loss 0.21114. 표본이 작고 생성식에 가정한 관계를 학습하므로 실제 모집단 성능·공정성·정확한 확률을 보장하지 않습니다. 실제 적용에는 시간 외부 검증, 확률 보정, 데이터 품질 및 공정성 검증이 필요합니다.

## 데이터 사전

|필드|의미 / 단위|
|---|---|
|borrower_id|합성 ID, 모델 제외|
|income|월 소득, 만원|
|balance|기준 시점 대출 잔액, 만원|
|rate|고정 연 금리, %|
|remaining|잔여 개월|
|other_payment|기타 부채 월 상환액, 만원|
|tenure|현 직업 근속, 년|
|credit|가상 신용점수, 350~1000|
|utilization|신용 한도 사용률, 0~1|
|savings|유동성 저축, 만원|
|payment|원리금균등 월 상환액, 만원|
|dti|(payment+other_payment)/income, 월 현금흐름 비율. 규제 DTI 아님|
|late30 / late6|최근 30 / 6개월 1일 이상 연체 횟수|
|lastlate|가장 최근 월 연체 여부, 0/1|
|maxdays|30개월 최대 연체일수|
|history_days|월 1→30 연체일수 JSON 배열, 정상 0 또는 3/10/35/65|
|next_month_late|다음 달 목표 0/1, 모델 제외|
|split|평가 분할, 모델 제외|

## 파일

- train.py: 데이터 생성, CV 탐색, 모델 선택, 평가, JS용 내보내기
- synthetic.csv: 전체 2,000명 및 30개월 이력과 목표
- docs/: 공유 가능한 정적 웹, 모델, 평가표, 가상 프로필
- verify.cjs / parity-fixtures.json: Python-JS 최종 테스트 예측 비교
- .github/workflows/pages.yml: main push 시 GitHub Pages 배포

## GitHub Pages 게시

빈 GitHub 저장소를 만들고 원격을 연결한 다음 main을 push합니다. Settings → Pages → Source를 GitHub Actions로 선택하면 포함된 워크플로가 docs를 게시합니다. 별도의 서버 또는 API 키는 필요 없습니다. Google Fonts 사용 시 글꼴 요청만 외부로 전송되며 고객 입력은 전송하지 않습니다.
